# مواصفات تتبّع الطلب في تطبيق Flutter

## الهدف

تمكين العميل من متابعة موقع مندوب الطلب على الخريطة، وتمكين تطبيق المندوب من إرسال موقعه أثناء توصيل هذا الطلب فقط.

## تدفق التتبّع

1. يبدأ التتبّع عندما تصبح حالة الطلب حالة توصيل نشطة، وفق الحالة التي يعتمدها النظام.
2. يطلب تطبيق المندوب إذن الموقع، ثم يرسل إحداثياته المرتبطة برقم الطلب.
3. يفتح العميل تفاصيل الطلب، فيجلب التطبيق آخر موقع معروف ثم يستقبل التحديثات الحية.
4. يتوقف إرسال الموقع والاشتراك عند التسليم أو الإلغاء أو انتهاء تعيين المندوب.

## واجهات الربط

### تطبيق المندوب: إرسال الموقع

`POST /api/orders/{order}/delivery-location`

يرسل الطلب مع مصادقة المستخدم والحقول التالية:

- `latitude`: خط العرض.
- `longitude`: خط الطول.
- `heading`: اتجاه الحركة بالدرجات.
- `speed`: السرعة.
- `recorded_at`: وقت تسجيل الموقع بصيغة ISO 8601.

ملاحظة: الـ API الحالي يتطلب الحقول الخمسة. يجب إرسال القيم المتاحة، والتنسيق مع مسؤول الـ API إذا لم تتوفر السرعة أو الاتجاه على الجهاز.

### تطبيق العميل: جلب آخر موقع

`GET /api/orders/{order}/delivery-location`

الاستجابة تتضمن `order_id`, `lat`, `lng`, `heading`, `speed`, `recorded_at`. إذا لم يصل موقع بعد، تعرض الواجهة حالة انتظار بدل وضع علامة غير صحيحة على الخريطة.

## التحديثات الحية

- اشترك في قناة الطلب الخاصة `order.{order_id}` بعد المصادقة.
- استمع إلى حدث `.delivery.location.updated`.
- بيانات الحدث: `order_id`, `lat`, `lng`, `heading`, `speed`, `recorded_at`.
- لا تستخدم قناة عامة لموقع المندوب.
- حدث `tracking.started` موجود بالـ Backend لكنه غير مفعّل حاليًا؛ لا تعتمد عليه لبدء الواجهة قبل تأكيد تفعيله وتوحيد القناة مع مسؤول الـ API.

## المطلوب في تطبيق المندوب

- طلب إذن الموقع عند بدء توصيل الطلب، وشرح سبب طلب الإذن.
- إرسال تحديثات الموقع للطلب المسند لهذا المندوب فقط، مع وقت الالتقاط.
- مراعاة أذونات ومحددات الموقع في Android وiOS، خصوصًا عند العمل في الخلفية.
- إيقاف تتبع الموقع عند تسليم الطلب أو إلغائه أو فقدان تعيينه أو تسجيل الخروج.
- عدم الاستمرار في إرسال الموقع بعد إغلاق التوصيل، وتقليل تكرار التحديثات لتوفير البطارية والبيانات.

## المطلوب في تطبيق العميل

- جلب آخر موقع عند فتح تفاصيل الطلب، ثم الاشتراك بالتحديثات الحية.
- عرض الخريطة وعلامة المندوب، وتحريك العلامة عند وصول إحداثيات جديدة.
- تدوير علامة المندوب باستخدام `heading` إذا كانت القيمة متاحة.
- إظهار وقت آخر تحديث والتنبيه إذا صار الموقع قديمًا.
- إلغاء الاشتراك عند مغادرة تفاصيل الطلب، وإعادة جلب الموقع وإعادة الاشتراك بعد عودة الاتصال.
- إيقاف واجهة التتبّع عند اكتمال الطلب أو إلغائه.

## حالات يجب تغطيتها

- تحميل أول موقع، وعدم وصول أي موقع حتى الآن.
- رفض إذن الموقع أو تعطيل خدمة الموقع على جهاز المندوب.
- انقطاع الإنترنت أو البث وإعادة الاتصال.
- فشل API أو انتهاء جلسة المستخدم.
- وصول موقع قديم أو غير صالح؛ لا تعرضه على أنه مباشر.
- عدم تكرار الاشتراك بالقناة أو إرسال تحديثات بعد انتهاء التتبّع.

## معايير القبول

- يستطيع المندوب المعيّن إرسال موقع الطلب، ولا يرسل التطبيق موقعًا لطلب آخر بالخطأ.
- تظهر آخر إحداثيات محفوظة للعميل، ثم تتحدث العلامة عند وصول حدث جديد.
- لا يمكن للعميل الاشتراك إلا بقناة الطلب المسموح له بمتابعته، وتتم المصادقة على القناة الخاصة.
- يتوقف التتبّع في التطبيقين عند التسليم أو الإلغاء.
- تعرض الواجهة بوضوح حالات الانتظار، الموقع القديم، وفقد الاتصال.
